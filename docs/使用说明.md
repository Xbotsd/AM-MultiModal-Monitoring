# 使用说明

这套系统是什么、怎么装、怎么给数据、怎么跑、结果怎么读、哪些能引用哪些不能。

---

## 一、基本内容讲解

### 1.1 系统由两半组成

| 一半 | 回答的问题 | 在哪 |
|---|---|---|
| **测量链** | 这组传感器数据对应什么工艺状态？ | `CODE/`（原有分析脚本，未改动） |
| **决策层** | 这套传感配置下，**任何**算法最多能看到什么？要看到更多得付什么代价？ | `src/dbound/`，由 `ammonitor.decision` 调用 |

两者缺一不可。只看准确率，你不知道漏掉的那些缺陷是不是本来就不可能被看见；只看上界，你不知道工艺当下在做什么。

### 1.2 为什么不重写那些脚本

`CODE/` 里的脚本是产出论文图表的原始代码。重写成"漂亮"的包，等于把"实际运行的东西"换掉——而可复现性恰恰要求不换。

所以系统选择**包住**它们：

- `tools/scan_stages.py` 扫描 `CODE/**/*.py`，抽取 docstring、涉及的 `data/...` 路径、是否使用随机数，生成 `src/ammonitor/stages.json`；
- `ammonitor.registry` 读这个文件，回答"有哪些阶段、各自需要什么数据、属于哪类证据"；
- `ammonitor.pipeline` 在子进程里、以仓库根目录为工作目录执行脚本；**声明了但缺失的输入数据会让它直接拒绝运行**（退出码 2），而不是产出一个空结果冒充阴性结论。

有一个测试断言"磁盘上的脚本集合 = 注册表里的集合"，所以注册表不会悄悄漂移。

### 1.3 决策层在讲什么

对已知信号、加性噪声，匹配滤波器的偏转最大：

```
d' = ‖s‖ / σ
POD ≤ Φ( d' − z₁₋α )
```

任何检测器（含任何训练出来的模型）都不可能超过它，因为这一步只用了 Neyman–Pearson 引理和 Cauchy–Schwarz 不等式。

两个模态的差别只在于 `‖s‖²` 从哪来：

- **体数据**（CT、点云）：缺陷被点扩散函数模糊，`‖s‖² = E(a/L)`，低于体素按立方衰减、高于体素按 3/2 次幂；
- **瞬态**（声发射、激光超声）：缺陷是一个事件，`‖s‖²` 就是期望波形的平方范数，取决于事件占多少采样点。

推论：体数据里**分辨率压倒剂量**（体素减半 = 64 次重复扫描），瞬态里带宽和积分窗口压倒一切。

## 二、安装

```bash
git clone https://github.com/Xbotsd/AM-MultiModal-Monitoring.git
cd AM-MultiModal-Monitoring

python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # Linux / macOS

pip install -e .
pytest -q                     # 应显示 16 passed
```

`scikit-learn` 只有部分老脚本需要，可选装：`pip install -e .[ml]`。

不想安装也能用：`PYTHONPATH=src python -m ammonitor ...`。

## 三、把数据放好

数据集不入库（声发射 4.5 GB、激光超声 45 MB）。来源与许可见 `data/README.md`。

```
data/
├── epfl_acoustic/Deciphering AE/
│   ├── D1_rawspace_5000.npy     # 31 401 × 5 000 条波形
│   ├── D1_classspace_5000.npy   # 标签
│   └── …… D2–D4
├── laser_ultrasound/
│   ├── 201120_Ti_FMC_128ave.mat
│   └── X_lu.npy                 # 由 prepare_lu_v3 重新生成
└── phase_unwrap/、pointcloud/ …… # 由各阶段自己写出
```

放好后问系统当前能看到什么：

```bash
python -m ammonitor list
```

行首的 `!` 表示该阶段声明的某个输入路径不存在。**缺数据时不会运行**，而是返回退出码 2——这一点很重要，它避免了"跑了个寂寞"被当成阴性结果。

## 四、找阶段、跑阶段

```bash
python -m ammonitor list                      # 28 个阶段：来源 + 数据状态
python -m ammonitor info 1_acoustic:run_eplf_v12
python -m ammonitor run  1_acoustic:run_eplf_v12
```

`info` 会打印：脚本路径、docstring 摘要、它涉及的每一个 `data/...` 路径、是否用随机数、以及证据类别。

只跑"能作为工艺证据"的那一串：

```bash
python -m ammonitor chain measured --out results/chain.json
```

这个链条是从注册表推出来的，不是写死的：正好是声发射、激光超声、相位三组里标为 `measured` 的阶段。

## 五、用决策层

**命令行**：

```bash
python -m ammonitor bound --a 100 --L 40 --dI-over-sigma 5
```

读法：100 µm 缺陷、40 µm 体素、对比度 5 倍噪声 → 偏转 9.5，检出概率基本为 1；如果只要 90%，体素可以放宽到 66 µm。再粗，这个缺陷就在上界之外了。

**Python，体数据**：

```python
from ammonitor import decision
e = decision.volumetric_energy(a=100.0, L=40.0)
print(decision.pod(dI=5.0, sigma=1.0, energy=e))
print(decision.requirement(100.0, 5.0, 1.0, pod_target=0.9).voxel_max)
```

**Python，瞬态**：

```python
import numpy as np
from ammonitor import decision
e = decision.transient_energy(np.load("template.npy"))   # 期望波形
print(decision.pod(1.0, sigma=0.8, energy=e))
```

**实测例子**（EPFL 声发射，真实数据）：

```bash
python tools/ae_detectability.py --data-root <数据根目录> --set D1
```

结果：`d' ≈ 4.0–4.2`，POD ≈ 0.96（α = 0.01）。**偏转 4 就只对应 0.96，再多也没有**——这正是测量链必须做特征工程、而不是模板匹配的原因。

## 六、证据分类（这一节最重要）

```bash
python -m ammonitor report
```

输出三个互斥清单：

| 类别 | 阶段数 | 能引用为什么 |
|---|---|---|
| `measured` | 9 | 工艺证据 |
| `simulated` | 7 | 方法证据 |
| `derived` | 12 | 都不是；统计与图 |

**融合与闭环控制那七个模块是仿真**（自造传感器数据、带随机种子、不读任何实测采集）。把它们的精度和声发射实测结果平均成一个"系统精度"，正是这个报告模块要阻止的事。

规则只有一句：**不在 `process_evidence` 清单里的数字，不能当作工艺事实引用。**

## 七、新增一个阶段

1. 把脚本放到对应的 `CODE/<模块>/` 目录；
2. `python tools/scan_stages.py` 重新生成注册表（它会读 docstring、`data/...` 路径、是否用随机数，自动给证据类别）；
3. `python -m ammonitor list` 检查分类；
4. `pytest -q`（有个测试会断言磁盘脚本与注册表一致，新阶段自动被覆盖）。

如果自动分类不对，改**源码**（docstring 或路径），不要改 JSON——JSON 是生成的。

## 八、常见问题

**所有阶段都带 `!`。**
你在一个没有数据集的 clone 里，这是全新克隆的正常状态，见第三节。

**`run` 返回退出码 2。**
该阶段声明的输入不存在。放数据，或者在你确认脚本能容忍的情况下加 `--allow-missing-data`（多数脚本不能）。

**为什么融合被标成 `simulated`？**
因为它自己生成传感器数据。这个标签是扫描源码得出的，不是人写的断言；哪天它开始读实测文件，下次重建注册表就会变。

**决策层不用行不行？**
行。`list / run / chain / report` 只依赖注册表。决策层（`src/dbound/`）是独立包，有自己的测试，放在这里是为了一次 clone 拿到全套。

**`python -m ammonitor` 提示找不到模块。**
`pip install -e .`，或者前面加 `PYTHONPATH=src`。
